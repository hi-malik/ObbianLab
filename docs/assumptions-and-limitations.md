# Assumptions, simulations and remaining evidence

The repository implements every scenario locally, but it must not be described as a completed AWS production assessment before the remaining account-dependent demonstrations are run.

- **Local identity:** `AUTH_MODE=demo` is an explicit loopback-only shortcut. Strict mode verifies signed expiring assessment tokens and resolves roles from PostgreSQL; token issuance is an operator CLI. OIDC login, MFA and session revocation are not bundled.
- **Allocation:** the professional publishes current GPS presence. Candidates satisfy category, availability, freshness, service radius and a configurable ETA budget. ETA is straight-line distance at 30 km/h plus 120 seconds; road routing, traffic, location attestation and fraud detection are excluded.
- **AI:** an English/Hindi parser provides the offline demonstration. Hosted structured-intent, embedding, answer generation and audio transcription adapters are implemented and contract tested. Live behavior requires provider credentials; local benchmark results do not measure model quality or inference latency.
- **RAG:** the offline encoder is a deterministic hash vector with lexical reranking and extractive answers. Configured deployments use semantic embeddings and generated cited answers; the 384-dimensional encoder identity is stored and incompatible queries fail closed. Six synthetic retrieval queries are regression evidence, not an enterprise accuracy study. PDF extraction supports text PDFs under resource limits; OCR is not implemented.
- **Payments:** default Compose uses an explicit HMAC gateway and settlement simulator. Stripe test PaymentIntents, refunds, signed webhooks and independent reconciliation are implemented; only `sk_test_` credentials are accepted. No real money is charged. Provider-backed execution requires account credentials. Strict operation uses immutable server-owned flat-fee quotes from SERVICE_PRICES_JSON and rejects price/currency tampering. Explicit unpriced demo mode remains a simulation. Connect test transfers move funds to a connected Stripe balance, not a real bank payout.
- **Cloud:** Terraform/Kubernetes/CI code is supplied and locally validated. No AWS account, region, hostname, certificate or Git remote was supplied. Per user direction, AWS provisioning is deferred until audit/fixes are finished. A local Docker deployment is not evidence of AWS, multi-AZ failover, zero-downtime rollout or rollback.
- **Release compatibility:** migration 006 changes the reporting key to include currency. The pre-review reporting image cannot be rolled back across that change. This initial upgrade requires a coordinated reporting worker restart; later zero-downtime releases must maintain expand/contract compatibility. Kafka/outbox retain work during that restart.
- **Performance:** pipeline throughput exceeds the two-million/day average in a short measured local run. It is not a 24-hour soak, peak-load guarantee or AWS capacity result. Availability and AI/RAG benchmarks are separate local baselines with workloads disclosed.
- **Operations:** database PITR, cross-AZ disaster recovery, provider outages, live alerts and restore RPO/RTO need account-specific drills. Proposed RPO/RTO values are design objectives, not achieved SLAs. Long-term location/audit/inbox retention is deployment policy.
